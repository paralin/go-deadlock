## Introduction

**go-deadlock** is a [Deadlock](https://store.steampowered.com/app/1422450/) client plugin for [go-steam](https://github.com/paralin/go-steam).

Games implemented:

 - [dota2](https://github.com/paralin/go-dota2)
 - [deadlock](https://github.com/paralin/go-deadlock)
 - [underlords](https://github.com/paralin/go-underlords)

## Usage

```go
cl := steam.NewClient(...)
dl := deadlock.New(cl, logrus.StandardLogger())
```

## SOCache Mechanism

The client mirrors the shared-object caches the GC subscribes it to: the
account's profile, heroes and challenges, its party and its match lobby. Each
cache belongs to an owner, and holds objects by type and key fields. The client
emits a `*socache.CacheEvent` on its event stream for every object created,
updated or destroyed, with the owner and type, and clears the caches when the
session ends.

```go
import (
	"github.com/paralin/go-deadlock/cso"
	devents "github.com/paralin/go-deadlock/events"
	gcmm "github.com/paralin/go-deadlock/protocol"
	"github.com/paralin/go-deadlock/socache"
)

switch ev := event.(type) {
case *socache.CacheEvent:
	if hero, ok := ev.Object.(*gcmm.CSOAccountHeroInfo); ok {
		// ev.EventType tells whether the hero was created, updated or destroyed.
	}
case devents.ClientStateChanged:
	// ev.NewState.Party, Lobby and HideoutLobby follow the caches.
	// ev.NewState.MatchID() names the party's match once its lobby forms.
}
```

`GetCache().Get` and `GetCache().Range` read the current objects.
`GetCache().RegisterType` decodes a type that has no built-in schema in `cso`.

## Implementation Generation

This project makes use of a dynamic API generator (apigen) designed to
automatically interpret Valve's various naming conventions into a intermediate
API scheme representation, which is then converted into Go code.

The base API implementation is generated by the [apigen](./apigen) code. Using heuristics, request IDs are matched to response IDs, and events and action-only requests are identified. Some manual tweaking is done in the overrides file.

Next, the API information is used to build a Go code-gen set of implementations around the `MakeRequest` request tracking mechanism.

This means that ALL of the Deadlock GC API will be available in this codebase, although only some of it is documented.
